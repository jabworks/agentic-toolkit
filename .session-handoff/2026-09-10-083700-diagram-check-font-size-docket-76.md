### Key discoveries

- In Chrome, a `text { font-size }` rule overrides every `font-size` attribute in the SVG and a `.class` rule overrides both; inheritance from `<g font-size>` loses to either rule. The 09-08 fixtures had been rendering at 13px throughout, so the "Widget host row touches its border" note in the 09-08 handoff was a font-size artefact, not a 0.6 em problem.
- The browser default when nothing sizes SVG text is 16px, not 13; the 13 the checker used came from the fixtures' own CSS, which the checker could not read.
- Geist is not installed on this WSL machine — `--sans` measures on DejaVu Sans (semibold 0.63 mean / 0.70 max em/char), the wide end of the token stack; mono is font-independent at 0.6.
- The chrome-devtools MCP could not launch (another session's Chrome holds `~/.cache/chrome-devtools-mcp/chrome-profile`); `google-chrome --headless=new --screenshot` / `--dump-dom` with a scratch `--user-data-dir` did everything needed.
