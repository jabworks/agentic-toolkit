what & why

Compared condux against its model, obra/superpowers, and found two real gaps: subagent-driven-development lacks the file-handoff and compaction-resilience mechanics superpowers built after documented failures (lost progress after compaction, 42k-char pasted-history dispatch prompts), and condux's own Node infrastructure (annotate-server.js, preview-server.js, scaffold.sh) has zero automated verification. A third, smaller gap — nothing enforces /workflow as the actual entry point when a downstream skill is invoked directly — gets the cheapest fix that closes it, not a new subsystem.

chosen approach

Chosen
Port proven mechanics + add CI, using existing conventions

Four independent workstreams: (1) subagent-driven-development gets a progress ledger, file-based task handoff scripts, and explicit model-tiering; (2) GitHub Actions CI runs stdlib-only smoke tests against the toolkit's own scripts/servers plus a dist/skills mirror-drift check; (3) brainstorm, write-plan, and finalize check for an existing artifact on disk before falling back to asking conversationally; (4) write-plan always offers plan-review as a soft gate after saving — review in the browser or go straight to implementation — via annotate-server.js --steer, regardless of whether /workflow drove it.

Each workstream ports a documented, battle-tested mechanism rather than inventing a new one — superpowers' own incident history justifies the ledger and file-handoff; the CI checks target infrastructure condux already ships but never verifies; the soft-gate reuses condux's existing gate style instead of adding a new state-tracking primitive.

alternatives rejected

Worktree isolation bigger structural addition than the other gaps justify this round
Workflow-level ledger superpowers has no equivalent — would be an unvalidated experiment, not a port
vitest / jest devDependency node:test + node:assert already cover the need — no new dependency justified
Unconditional meta-skill coercion would undo condux's own soft-gate differentiator to patch a continuity gap
Fully reconcile plan-review paths workstream 4 resolves the write-plan/CP-1 overlap; ExitPlanMode hook stays separate, untouched

key constraints

  • No new runtime or dev dependencies anywhere in the repo
  • Ledger scoped to subagent-driven-development only, not /workflow checkpoints
  • dist/ remains a verbatim mirror of skills/ — CI enforces, doesn't change, this invariant
  • Continuity soft-gate and plan-review offer both stay soft — ask, never block
  • Plan-review offer (workstream 4) applies to write-plan's doc (LARGE) only — not MEDIUM's inline plan

out of scope

  • Git worktree isolation for subagent-driven-development
  • A durable ledger/state file for /workflow's own phase checkpoints
  • The ExitPlanMode hook path — remains separate from write-plan's new offer
  • Adopting a JS test framework or any new package dependency
  • Superpowers-style unconditional meta-skill enforcement
