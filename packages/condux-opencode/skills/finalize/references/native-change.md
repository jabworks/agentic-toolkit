# Native-change check

A mobile app has two layers. JavaScript reloads in seconds; the native binary
(Kotlin/Swift, native modules, the compiled app config) only changes when the
app is **rebuilt and reinstalled**. None of the JS gates — typecheck, lint,
format, tests — compile the native layer, so a change that touches it can pass
every gate and still not exist in the app on the device. This check makes that
visible. It never blocks.

Its verdict is used in three places: finalize reports it, workflow mentions it
at tier confirmation, and live-verification acts on it before driving the app.

## When it applies

Only in an app project: an `expo` or `react-native` dependency in
`package.json`, or a committed `android/` or `ios/` directory. Anywhere else,
omit the `Native` line entirely — a web repo gets no noise from it.

## The verdict

Two outcomes. Name the escalation, lightest first:

| Verdict | Means | To see the change |
|---|---|---|
| **JS only** | Nothing in the diff reaches the binary | Fast Refresh or a JS reload; restart the app process if a native module is left in a bad state |
| **Native rebuild** | The diff touches something compiled into the binary | Rebuild the app (dev client or release build) and reinstall it; clear the app's data too when the change touches native state that persists across installs (notification channels, permissions, keychain entries, database schema created natively) |

## How to decide

**Precise — when a recorded fingerprint exists.** Expo projects can hash
their native layer. If `.condux/native/fingerprint-<platform>.json` exists
(recorded after the last native build — see below), generate a fresh one the
same way and compare the two JSONs' `hash` fields:

```bash
# with expo-updates installed — per platform, the same hash EAS uses:
npx expo-updates fingerprint:generate --platform android > .condux/native/now-android.json
# without it — covers both platforms at once:
npx @expo/fingerprint fingerprint:generate > .condux/native/now-all.json
```

Equal hashes are **JS only**. Different hashes are **Native rebuild** — then
name what moved with
`npx @expo/fingerprint fingerprint:diff <recorded> <now>`. The `now-*` file is
overwritten on every check. Compare against the recording for the platform
you are building; a both-platforms fingerprint also moves on iOS-only changes,
so say which one you used. The fingerprint covers what a path list cannot
see — autolinked native modules inside `node_modules`, config-plugin output,
patches to native packages.

**Core — always available.** Otherwise, read the task's diff. Any of these
means **Native rebuild**:

- local native code: `modules/**` (Expo modules), any `.kt`, `.java`, `.swift`,
  `.m`, `.mm`, `.cpp`, `.h` file, `*.podspec`, `build.gradle*`
- committed native projects: `android/**`, `ios/**` (if they are generated by
  prebuild, the real change is upstream of them — find it)
- app config compiled into the binary: in `app.json` / `app.config.*`, the
  `plugins`, `permissions`, `android`/`ios` blocks, `name`, `scheme`, `version`,
  `runtimeVersion`, splash and icon assets; any config-plugin source file
- dependencies: a package added, removed or version-changed in `package.json`
  that ships native code (it has an `android/` or `ios/` directory, or an
  `expo-module.config.json`), and every Expo SDK or React Native upgrade
- patches: `patches/**` touching a native package, `cng-patches/**`
- `eas.json` build-profile changes that alter what is compiled

When a file's effect is unclear, say **Native rebuild** and name the file —
a wasted rebuild costs minutes; a verification against a stale binary costs
the whole verification.

**Project override.** If `AGENTS.md` lists the project's native paths or its
rebuild command, those win over the lists above.

## Recording the fingerprint

The precise check needs a baseline, so whoever rebuilds and installs the app
records one straight after the install succeeds:

```bash
mkdir -p .condux/native
npx expo-updates fingerprint:generate --platform android > .condux/native/fingerprint-android.json
# or, without expo-updates:
npx @expo/fingerprint fingerprint:generate > .condux/native/fingerprint-all.json
```

It lives in `.condux/` (working state, gitignored) because it describes the
build installed on *this* machine's device or emulator, not the repository.
Only Expo projects record one — the fingerprint reads the Expo config, and
`npx` fetches the tool if it isn't installed. Bare React Native and native-only
projects use the core check alone.

## Reporting

In finalize's output, beside `Env`:

```
Native     ✓ JS only (android fingerprint unchanged) — a reload shows it
Native     ⚠ native rebuild — modules/app-lock/android/…/AppLockModule.kt, app.json plugins
             not compiled by any gate; rebuild with `npx expo run:android` and reinstall before verifying
```

Take the rebuild command from `AGENTS.md` or `package.json` scripts; if
neither names one, say "rebuild the app" and stop — never guess a build
command. On **Native rebuild**, finalize ends "Ready to commit — native rebuild
needed before it can run": the code is clean; the app just does not contain it
yet.
